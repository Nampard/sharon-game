# ADR-0003: 사람 인식은 YOLO pose + ByteTrack 추적으로 한다

- 상태: 제안됨 (Proposed)
- 날짜: 2026-11-25

## 배경

게임에는 다음이 필요하다.

1. 한 화면에 **여러 명**(목표 2~6명)을 동시에 인식
2. 프레임이 바뀌어도 **같은 사람을 같은 ID로** 유지 (누가 탈락했는지 알아야 함)
3. 몸 전체가 아닌 **팔·다리의 작은 움직임**도 잡기
4. 일반 노트북 CPU에서 **15fps 이상**

검토한 후보:

| 후보 | 다인원 | 추적 ID | 미세 움직임 | 비고 |
|---|---|---|---|---|
| 프레임 차분(배경 빼기)만 사용 | △ | ✗ | ○ | 누가 움직였는지 구분 불가, 조명 변화에 취약 |
| MediaPipe Pose | △ (Tasks API에서 다인원 가능하나 불안정) | ✗ | ○ | 추적 기능 없음 |
| **YOLO11n-pose + ByteTrack (Ultralytics)** | ○ | ○ (내장) | ○ (관절 17개) | AGPL-3.0 라이선스 |
| YOLO 사람 박스 + 박스 내부 프레임 차분 | ○ | ○ | ○ | 포즈보다 가볍지만 노이즈 많음 |

## 결정

- 모델: **`yolo11n-pose`** (가장 작은 포즈 모델). 입력 해상도 640 기본, 느리면 480.
- 추적: Ultralytics 내장 **ByteTrack** (`model.track(..., persist=True, tracker="bytetrack.yaml")`).
- 각 사람마다 프레임별로 `track_id`, `bbox`, `keypoints(17×(x,y,conf))` 를 얻는다.
- 인식 모듈은 `Detector` 인터페이스(`detect(frame) -> list[Person]`)로 감싸서, 나중에 ONNX Runtime 구현이나 다른 모델로 교체할 수 있게 한다.
- 인식은 **별도 스레드**에서 돌리고 최신 결과만 게임 루프에 넘긴다 (렌더링 fps가 인식 fps에 묶이지 않게).

### ID 흔들림 대책

ByteTrack도 사람이 겹치거나 화면 밖으로 나가면 ID가 바뀔 수 있다.

- **로비(참가 등록) 단계**에서 보인 ID만 참가자로 등록한다. 게임 중 새로 생긴 ID는 무시한다.
- 참가자 ID가 사라졌다가 근처에 새 ID가 생기면, 마지막 박스와의 IoU/중심 거리로 **재연결**한다.
- 재연결이 안 되면 "화면 이탈"로 표시하고, 멈춤 구간에 이탈하면 탈락 처리한다(원작 규칙 느낌 유지).

## 결과

- 장점: 다인원 + 추적 + 관절 정보를 한 번에 얻어 구현이 단순하다.
- **라이선스 주의**: Ultralytics는 AGPL-3.0이다. 개인/교육용 배포는 문제없지만, 상업적으로 소스를 닫고 배포하려면 Enterprise 라이선스가 필요하다. 상업화 시 RTMPose/ONNX 등 다른 모델로 교체하는 새 ADR을 작성한다.
- 사람이 서로 많이 겹치는 좁은 공간에서는 추적이 불안정하다 → 플레이 공간 안내(사람 간 간격) 화면을 둔다.
