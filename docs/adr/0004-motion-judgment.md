# ADR-0004: 움직임 판정은 "몸 크기로 정규화한 관절 이동량 + 유예 시간"으로 한다

- 상태: 제안됨 (Proposed)
- 날짜: 2026-11-25

## 배경

"멈춤" 구간에 움직인 사람만 정확히 탈락시켜야 한다. 문제점:

- 카메라에서 **가까운 사람은 픽셀상 크게** 움직이고, 먼 사람은 작게 움직인다.
- 숨쉬기, 몸의 미세한 흔들림, **포즈 추정 자체의 떨림(jitter)** 때문에 가만히 있어도 좌표가 변한다.
- 사람은 "멈춰!" 소리를 듣고 실제로 멈추기까지 **반응 시간(약 0.3~0.5초)** 이 필요하다.
- 오판(가만히 있었는데 탈락)은 게임 경험을 크게 망친다 → **오탐을 미탐보다 더 나쁘게** 본다.

## 결정

### 판정 절차 (참가자별, 매 프레임)

1. **유예 시간**: 영희가 뒤돌아본 직후 `grace_ms`(기본 500ms) 동안은 판정하지 않는다.
2. **기준 자세 저장**: 유예가 끝난 뒤 첫 `N`프레임(기본 3)의 관절 좌표 평균을 기준(baseline)으로 저장한다.
3. **평활화**: 최근 `N`프레임 관절 좌표의 이동 평균을 현재 자세로 쓴다.
4. **이동량 계산**: 기준·현재 모두 신뢰도 `conf >= 0.5` 인 관절만 사용해
   관절별 `|현재 - 기준| / bbox_height` 를 구하고, 그중 **두 번째로 큰 값**을 score로 쓴다.
   - 최댓값을 쓰면 포즈 추정이 관절 하나에서 튈 때 오판한다.
   - 중앙값을 쓰면 팔만 움직이는 경우(17개 중 2~3개 관절)를 놓친다. (최초 안에서 변경)
   - 두 번째 값은 팔(팔꿈치+손목)·다리(무릎+발목)처럼 함께 움직이는 관절은 잡고 단일 관절 튐은 무시한다.
5. **탈락 조건**: 평활화된 score가 `threshold`(기본 0.04, 즉 키의 4%)를 넘는 상태가
   **연속 `confirm_frames`(기본 3)프레임** 지속되면 탈락.
6. 박스 중심 이동량(걸어서 다가옴)도 같은 방식으로 별도 체크해 둘 중 하나라도 넘으면 탈락.

### 설정과 보정

- `threshold`, `grace_ms`, `confirm_frames` 는 **난이도(쉬움/보통/어려움) 프리셋**으로 설정 파일에 둔다.
- 첫 실행 시 **보정 모드**: 참가자가 5초간 가만히 서 있는 동안 jitter 분포를 재서, threshold 하한을 자동으로 정한다 (jitter 평균 + 4σ 보다 작게 내려가지 않음).
- 디버그 오버레이로 각 사람 머리 위에 실시간 score를 표시할 수 있게 한다 (튜닝용).

### 승리 조건

- 모니터 앞에 둔 **물리 버튼**(대형 키보드 스위치, 설정 `win_key` 로 키 지정, 기본 스페이스·Enter — 게임 중에만 승리 버튼, 메뉴에선 스페이스가 진행 키)을 누르면 승리.
- 버튼은 누가 눌렀는지 모르므로, 그 순간 **화면에 보이는 생존자 중 bbox가 가장 큰(카메라에 가장 가까운) 사람**을 누른 사람으로 본다.
- `button_ends_game=true`(기본): 첫 버튼으로 게임 종료. `false`: 누른 사람만 통과하고 나머지는 계속.
- 제한 시간 안에 아무도 누르지 못하면 생존자 전원 "시간 초과" 탈락.
- RED 중 화면에서 `missing_out_ms`(기본 1.5초) 이상 사라진 참가자는 "화면 이탈" 탈락.

## 결과

- 관절 기반이라 팔만 살짝 움직여도 잡을 수 있고, 거리와 무관하게 공정하다.
- 연속 프레임 확인 때문에 탈락 판정이 최대 ~0.2초 늦어진다(15fps 기준). 연출상 문제없다.
- 값들은 실제 환경(조명, 카메라 화각)에서 튜닝이 필요하다 → 판정 로직은 순수 함수로 분리해 녹화 영상으로 단위 테스트한다.
